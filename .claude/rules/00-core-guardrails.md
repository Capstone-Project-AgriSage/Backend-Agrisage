# Core Guardrails

- Treat `AGENTS.md` as the concise project map.
- Treat `docs/reference/` as authoritative detailed specifications.
- Do not guess project-specific business rules when a relevant source exists.
- If authoritative documents conflict, report the conflict instead of silently choosing.
- Keep task scope surgical; do not refactor unrelated modules.
- Never commit secrets or credentials.
- Never claim build/test/migration success without running the relevant command.
- Prefer existing repository patterns over inventing new abstractions.
- Read code before making claims about code that already exists.
- Do not load every context document by default; use progressive disclosure.
